# Phase 2B Gate 1: GPU-resident binary64 GMRES

11 October 2026. Gate 1 implementation and independent validation complete. No outer IR, GPU SPAI construction, mixed precision, bucketing or performance work was performed in this stage.

Intended contract: retain [the binding CPU specification](PHASE2A_ALGORITHM_SPEC.md), one-pass ascending MGS, unrestarted left GMRES, two separate SpMVs P*(A*v), identical estimated-trigger/recomputed-relative stopping semantics and named statuses. Immutable CPU A/P are uploaded once. No mathematical method/threshold is changed; GPU reduction/FMA rounding may differ from CPU, so histories are not promised bitwise equivalent.

All Krylov/candidate/residual vectors remain device-resident throughout iteration. cuSPARSE performs binary64 nontranspose CSR_ALG2 products; cuBLAS typed binary64 dot/copy/axpy `_64` APIs perform vector arithmetic. Small Hessenberg, Givens and triangular coefficient bookkeeping lives on the host and observes GPU scalar results; every such scalar observation and finite-status flag is counted. Candidate/basis diagnostic snapshots are copied device-to-device and downloaded only after termination, not within Arnoldi. Literal division and finite-entry status kernels retain the specified normalization/range semantics. All GMRES norms use the explicitly authorized safe-scaled device primitive described below.

## Sources and native precision controls

Carson--Khan [P1 Algorithm3.1](https://arxiv.org/pdf/2202.10204v2) and the [published BSPAI article sections3--4](https://link.springer.com/article/10.1007/s00366-025-02187-z) establish the central left-preconditioned refinement context; the exact frozen GMRES and exceptional-case policies remain in the binding specification. [cuBLAS documentation](https://docs.nvidia.com/cuda/cublas/index.html) establishes typed double Level1 APIs, host-output scalar synchronization, `_64` indices and math/atomics controls; [cuSPARSE](https://docs.nvidia.com/cuda/cusparse/index.html#cusparsespmv) supplies the two sparse products. [Loe et al. section4](https://arxiv.org/pdf/2109.01232) provides prior GPU GMRES context with host small-system bookkeeping, but its right-preconditioned/restarted/CGS2 method is not substituted for this left/unrestarted/one-pass MGS baseline.

The handle explicitly sets and reads back exactly `CUBLAS_PEDANTIC_MATH`, uses `CUBLAS_ATOMICS_NOT_ALLOWED`, HOST scalar pointer mode and the same dedicated nonblocking stream as cuSPARSE. The reproducible script sets `CUBLAS_EMULATE_DOUBLE_PRECISION=0`; no emulated/TF32/mixed compute mode is requested. Custom kernels compile with `--fmad=false`, default precise division/square-root and no fast math; `/fp:strict` controls host code. These compiler flags do not control prebuilt vendor-library reductions/FMA. Native pedantic controls are explicit project precision choices, not paper requirements.

## Verified primitive discrepancy and authorized response

The first vendor-norm GPU draft produced330 checks with five failures localized to the unchanged identity/subnormal RHS fixture. For a single nonzero `2^-1030`, the norm should exactly equal `8.6916947597937554e-311`; the returned norm was `5.1806537865363094e-318`, corrupting normalization and causing breakdown. The standalone `src/cuda_norm_probe.cpp` confirms exact input readback and the same discrepancy for both `cublasDnrm2`/`cublasDnrm2_64`, n1/n2, HOST/DEVICE scalar output and DEFAULT/PEDANTIC math. For denorm_min both return zero; normal `2^-900` and min-normal `2^-1022` cases agree. Loaded DLL `C:/Program Files/NVIDIA GPU Computing Toolkit/CUDA/v13.4/bin/x64/cublas64_13.dll` reports130700, with emulation environment0. Every API status and stream completion was checked. This is verified local behavior, not a claim that all cuBLAS versions/platforms are defective or that FTZ caused it.

Parent explicitly authorized a deterministic safe-scaled device norm for **all** GMRES norms, not a hidden subnormal-only fallback. It uses a one-thread ascending-entry scale/sumsq recurrence matching the mathematical strategy in [Netlib's historical DLASSQ](https://www.netlib.org/lapack/lapack-3.1.1/html/dlassq.f.html): maintain a maximum magnitude and sum of squares relative to that scale, then return `scale*sqrt(sumsq)`. This is a serial debugging realization, not optimized or claimed bitwise identical to current LAPACK/CPU hypot. It avoids squaring unscaled extreme entries and handles representable subnormal norms. Nonfinite inputs/results remain explicit failures. `cuda_safe_norm2` exposes the primitive for independent tests. The Euclidean norm, tau and exact-zero decisions are unchanged; rounding/reduction realization is an explicitly documented project change. Literal device `v[i]/beta` avoids reciprocal overflow from `1/beta` followed by Dscal. No RHS rescaling, reorthogonalization, restart or tolerance relaxation was added.

## API, residency and transfers

`cuda_left_preconditioned_gmres` accepts canonical CPU CSR A/P, RHS, existing options and optional initial guess; returns the existing solver/status/history shape plus transfer accounting. Each call uploads immutable A/P once and retains them throughout that solve; cross-solve reuse/outer IR is not implemented. The wrapper rejects malformed canonical CSR, invalid dimensions/vectors/options, and checks signed64 index/byte counts. Runtime/device/allocation errors are checked exceptions, never CPU fallbacks; numerical overflow in iteration becomes the existing numerical_failure status.

Host/device transfers are bounded and explicit:

- Initialization: up to six immutable CSR arrays, RHS and initial guess are H2D uploads, counted in `vector_uploads` (the name includes CSR index/value arrays). An allzero matrix needs no CSR uploads.
- During Arnoldi: no vector uploads/downloads. Dot results, safe norms and finite-entry flags are scalar/status D2H observations; their category counts sum to `scalar_observations`. Finite flags follow vector operations without introducing a potentially overflowing norm merely to inspect entries.
- Host inputs during iteration: cuBLAS axpy coefficients, cuSPARSE alpha1/beta0 and the literal-division divisor are counted in `host_scalar_inputs` and category fields. Kernel/API dimensions and control metadata are ordinary command parameters, not Krylov vectors. Vendor-internal scalar copying is not independently CUPTI-profiled.
- Device-to-device only: basis storage, current candidate, last fully checked solution and per-iteration snapshot copies. Raw H/Givens/backsolve live on host; candidate construction uses GPU axpy in ascending basis order.
- Termination: final solution, completed candidate snapshots and recorded basis vectors are D2H downloads. Full histories permit independent diagnostics without downloading them while solving. Both Arnoldi vector-transfer counters must remain0.

This is GPU-vector-resident, host-controlled/scalar-synchronized GMRES, not a wholly device-controlled or low-synchronization solver. Matrices/vectors have RAII ownership, stream completion precedes teardown, and failures do not adopt unverified candidates. Snapshot storage adds O(n*cap) memory beyond basis storage; no performance optimization is claimed.

## Final gate evidence

The first vendor-norm draft intentionally remains recorded as a failed gate attempt: 330 checks contained five failures in the unchanged `2^-1030` identity-RHS case. Standalone validation isolated the behavior to both cuBLAS norm APIs in the loaded cuBLAS 13.7.0 DLL; transfers were bitwise correct. The failure was not hidden by changing `tau`, deleting the fixture, or using a subnormal-only fallback.

The authorized all-norm safe-scaled device recurrence then passed **871 C++ CUDA-GMRES checks with zero failures**, including every binary64 subnormal singleton, smallest-normal boundary, mixed magnitudes, nonfinite/range paths, deterministic repetitions, CPU-SPAI P, breakdown/cap/status paths, and GPU estimate-gap rejection. An independent 80-digit Decimal audit passed **383 checks**, covering 125 norm fixtures and 48 GMRES snapshots. The preserved `2^-1030` identity RHS succeeds exactly in one iteration; the main CPU/GPU infinity-norm solution difference is at most `4.4408920985006262e-16`, and the independent relative-residual difference is at most `1.1102230246251565e-16`.

At `tau=2e-16`, the GPU estimate-gap fixture records estimate `1.085730288427049e-16` but independently recomputed preconditioned relative residual `3.0067321592990152e-16`; it rejects success. Thus the original recomputed-residual acceptance policy is retained.

Residency telemetry on a three-iteration case reports eight initial uploads, eight post-termination downloads, zero Arnoldi vector H2D/D2H transfers, six dot scalar observations, twelve norm scalar observations, and 39 finite-flag scalar observations. This confirms vector residency but not a low-synchronization performance design.

Host execution of `cuda_gmres_tests.exe` and CUDA CTest passed; CUDA CTest is **2/2** (`cuda_gmres_tests`, `cuda_spmv_tests`). The existing CPU suite remains separately rerun at **946 checks, zero failures**, CTest **4/4**. GPU GMRES range behavior depends on the custom serial safe norm; it is a correctness baseline and not a performance claim. The cuBLAS subnormal norm discrepancy remains a documented local vendor-library limitation.

Gate 1 is approved. Subsequent hybrid GPU iterative-refinement work must preserve this norm implementation, left/unrestarted GMRES semantics, and all recorded tests.
